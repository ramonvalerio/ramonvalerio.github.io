# Spec 006 — Internationalization (PT/EN/JA)

## Status
Implemented

## Summary
The site supports Portuguese (default), English, and Japanese via a flat key-value
dictionary and a React context, with no routing/URL changes per locale.

## Requirements
- `src/i18n/translations.js` exports `translations` (one object per language code)
  and `languages` (code, label, country flag code for the switcher UI).
- `src/i18n/LanguageContext.jsx` exposes the current language and a `t` object (the
  active language's key-value map) to all components via `useLanguage()`.
- `LanguageSwitcher.jsx` renders circular country-flag icons; selecting one swaps the
  active language immediately (client-side only, no page reload).
- Every section (Hero, Header/Nav, PortfolioGrid, Expertise, Contact, Footer) pulls
  its copy exclusively from `t.*` keys — no hardcoded user-facing strings outside
  `translations.js`, except where content is explicitly meant to stay in English
  (e.g., "AI Engineer" subtitle).
- All three languages are kept in sync key-for-key; a missing key in `en`/`ja` falls
  back to `pt` at the `getProjects()` level for project data.

## Non-goals
- No automatic browser-locale detection — the user manually picks a language.
- No per-language routes/subdomains (this is a client-side swap, not SSR i18n).
